# Working in this repository

Read this before changing anything. It is short on purpose; follow the links.

## What MeshCall is

A typed, streaming RPC framework whose runtimes must behave identically:
`meshcall-py/` (Python), `meshcall-ts/` (TypeScript) and `meshcall-go/` (Go),
plus `meshcall-router/` (Go; the standalone Router that all peers connect
to, the `meshcall` CLI, the client generators and the conformance suite).
`docs/protocol.md` is the contract between them; `docs/architecture.md`
explains the runtime design; `docs/router.md` the Router.

## Invariants

1. **The protocol document comes first.** A behaviour change is made in
   `docs/protocol.md`, then in Go, Python and TypeScript, then covered by a
   scenario in `meshcall-router/conformance/scenarios.go` (which runs against
   every runtime's fixture) and, when it crosses generated clients, by
   `meshcall-py/tests/test_multilang_interop.py`.
2. **Three runtimes, one behaviour.** Error codes, `details` keys, timeouts,
   reconnect semantics and frame fields are the same everywhere. If you add
   an option to one runtime, add it to the other and document it.
3. **Generated code is never edited by hand.** Files whose first line says
   `Generated by MeshCall` are produced by `scripts/regenerate.sh`; CI fails
   if they drift. Change the generator, then regenerate.
4. **No stateful Router.** The Router holds only state that peers rebuild on
   reconnect or that may be lost harmlessly (caches). Do not add queues,
   persistence or anything a Router restart would lose that peers cannot
   recover. See issues #15–#18 for the stateless reliability plan.
5. **One way to do each thing.** Do not add a second API shape for something
   that already has one; replace the old one instead (see issue #20).
6. **Catch at compile time what can be caught at compile time.** Prefer
   structured arguments over strings so type checkers see the rule; runtime
   `ContractError` is the last line of defence, not the first.

## Strict mode

Set `MESHCALL_STRICT=1` whenever you write or change a service. Advisory
contract warnings (missing descriptions, unannotated mutating methods, …)
then fail at import / class definition (`@service`) with a `hint` saying exactly what to
add. `scripts/check.sh demos` already runs the demos this way. To check one
Python service by hand:

```bash
cd demo/showcase && MESHCALL_STRICT=1 uv run --locked --reinstall-package meshcall python -c "import showcase_demo.service"
```

Fix the finding rather than silencing it unless the silence is clearly
intended (`description=""`). See docs/architecture.md → Contract warnings.

## Recipe: changing a demo or best-practice service

1. Edit `service.py` / `service.ts` (add a docstring/description and, for
   mutating methods, an annotation — strict mode will insist).
2. `scripts/regenerate.sh <target>` (`quickstart`, `showcase`, `router`,
   `py2ts`, `best-practice`, `ts2py`) rewrites that demo's generated client.
3. Update the runner (`run.py` / `run.mjs` / `cli.ts`) to use the new method.
4. `scripts/check.sh py demos drift`.

## Exploring a running mesh

`meshcall-router/bin/meshcall router inspect --router ws://…` lists services,
instances, health and methods from the Router's Registry;
`meshcall call svc.method '{json}'` performs a call with contract-aware
error hints. Prefer these over writing throwaway scripts.

`skills/meshcall/SKILL.md` is the skill users install into *their* projects
with `meshcall init`; it is the agent-facing summary of this repository's
behaviour. When you change a CLI flag, an error shape or a service-definition
rule, update the skill in the same commit and run `scripts/regenerate.sh
skill` (the Go CLI embeds a copy; drift fails CI).

## One CLI

Contract export and client generation live in the Go `meshcall` CLI
(`meshcall-router/internal/codegen`, driven by `internal/cli/generate.go`).
Given `.py`, `.ts` / `.js`, or Go package (`./pkg`) sources, `meshcall export`
and `meshcall generate` start an in-process inspect-only Router (`InspectOnly:
true`) and invoke the language runtime exporter (`python -m meshcall.export`,
`node .../dist/export.js`, or `go run`) to register the discovered services over
WebSocket and collect their portable contracts. `uv run meshcall` and `npx
meshcall` are launchers (`launcher.py`, `launcher.ts`) that exec the binary.
Generator output is pinned byte-for-byte by `internal/codegen/testdata/*`
(contracts plus expected files); when you change a generator, update the
expected files in the same commit, then `scripts/regenerate.sh` and commit the
regenerated demo clients.

## Verify

```bash
scripts/check.sh          # everything CI runs: router build, Go, Python, TS, demos, drift
scripts/check.sh py demos # some parts: go | py | ts | demos | drift | conformance
scripts/regenerate.sh     # rewrite all checked-in generated clients (or name targets)
```

`scripts/check.sh` sets `MESHCALL_ROUTER_BINARY` and `MESHCALL_RUN_INTEROP=1`
for you. When running tools directly:

- Build the Router first: `go -C meshcall-router build -o bin/meshcall-router ./cmd/meshcall-router`
  and export `MESHCALL_ROUTER_BINARY=$PWD/meshcall-router/bin/meshcall-router`.
- Python interop tests are skipped unless `MESHCALL_RUN_INTEROP=1`.
- Demos are uv projects with `meshcall` as a path dependency; uv caches that
  build, so after editing `meshcall-py` run them with
  `uv run --locked --reinstall-package meshcall demo`.
- macOS has no `timeout(1)`; use the Bash tool's own timeout.
- TypeScript tests run against `dist/`; `yarn test` builds first.

## Conventions

- Branches: start from the latest `main` and name the branch
  `<type>/<domain>/<topic>`. `type` matches the commit type (`feat`, `fix`,
  `docs`, `test`, `build`, `refactor`, `chore`); `domain` is where the change
  lives: `go` (`meshcall-router/`: Router, CLI, codegen, conformance), `py`
  (`meshcall-py/`), `ts` (`meshcall-ts/`), `gort` (`meshcall-go/`), `docs`, `ci` (workflows,
  `scripts/`, release), `demo` (`demo/`, `best-practice/`), `skill`; join
  several with `+`. Examples: `feat/go+py+ts/windows-pipes`,
  `fix/ts/reconnect-race`, `docs/docs/http-calls`.
- Commits: Conventional Commits with a scope, `type(scope): summary`
  (`fix(ts): …`, `feat(router): …`, `docs(protocol): …`); the body may be
  English or Chinese. One logical change per commit; reference issues with
  `Closes #N`.
- Pull requests: one PR does one thing. Changes reach `main` through a PR
  once CI is green; delete the branch after merging. Never commit unrelated
  local changes, debug output, logs or screenshots, and never credentials,
  tokens, `.env` files or signing material (publishing uses GitHub secrets;
  see the release workflow).
- Errors carry a stable `code`, a human message, and `details` with
  `source` (`client` | `router` | `server`) and `reason` where useful. New
  codes go into the table in `docs/protocol.md`.
- Loguru-style `{}` placeholders in Python logging need `# noqa: PLE1205`.
- Keep comments to the *why*; the code says the what.
